# UX/UI аудит — eengineer.net (28.07.2026)

Роль: аудитор, оценка глазами целевого пользователя — 13–18 лет, инженерный студент, первый визит, телефон или ноутбук, нулевой контекст о продукте. Вкусовщина (шрифты, палитра как таковая) не рассматривается. Разобраны файлы: `Welcome.tsx`, `Auth.tsx`, `sign-in.tsx`, `Onboarding.tsx`, `LandingFeatures.tsx`, `SponsorMarquee.tsx`, `button.tsx`, `tailwind.config.js`, `index.css`.

## Реальные проблемы (по приоритету)

### 1. «Eye strain» — диагноз неверный, проблема существует
`#FFF8DC` (cornsilk) — уже тёплый off-white, на ~6% темнее белого. Затемнять его дальше бессмысленно и вредно: `corn-700 #8B6914` на нём даёт 4.6:1 — уже на грани AA, любое затемнение фона это добьёт.

Что реально вызывает жалобы:

- **Нет тёмной темы на pre-auth страницах.** `SettingsMenu` темы не переключает, next-themes лежит мёртвым грузом (комментарий в `SettingsMenu.tsx:14`). Подросток, сидящий вечером с телефона, получает светло-кремовый экран без опции. Это и есть «слишком ярко».
- **Резкий перепад light→dark.** Лендинг/auth — кремовые, дашборд — почти чёрный (`dark-900 #08080F`). Скачок при каждом входе — фактический источник дискомфорта.
- **Мелкий текст с низким запасом контраста.** Только в `Welcome.tsx` + `Auth.tsx` + `sign-in.tsx` — 14 вхождений 12–13px текста; caps-label 11px/0.16em (`text-label`) в corn-700. Формально AA проходит, на телефоне при солнце — нечитаемо.

**Рекомендация:** не трогать палитру. Дать переключатель темы на pre-auth (инфраструктура уже в проекте), поднять минимальный размер текста до 13–14px для body-copy.

### 2. Hero не говорит, что это за продукт
`Welcome.tsx:89–150`. Первый экран для человека с нулевым контекстом:

- H1 «Just Engineer It.» — слоган, не объяснение.
- Sub-copy начинается с «Every profile here is tied to a real GitHub account — no anonymous feedback, no bots» — это защита от возражения, которого у новичка ещё нет. Что можно *делать* — во втором предложении, мельком.
- `LandingFeatures` H2 продолжает: «No anonymous accounts. No bot answers.» — снова оборона вместо ценности.

13-летний за 5 секунд не поймёт: «сообщество инженеров-школьников, публикуешь проекты, следишь за дедлайнами соревнований». Это и есть «looks AI-generated» в переводе на конкретику — текст generic-оборонительный.

**Рекомендация:** первая строка sub-copy = что это и для кого. Анти-бот аргумент — вторым.

### 3. /auth — самая тяжёлая страница для новичка (главный приоритет)
`sign-in.tsx`, `Auth.tsx`. Проблемы конкретные:

- **Жаргон трёх уровней доступа:** «Full access», «Limited preview», «verified Builders», «preview» — подросток на первом визите не знает ни одного из этих слов. Три бейджа + разделитель + amber-баннер = ~90 слов текста, чтобы объяснить внутреннюю модель доступа, которая пользователя не должна волновать до входа.
- **Warning-баннер (`TriangleAlert`, amber) для нейтральной информации** (`sign-in.tsx:131–139`). Иконка-треугольник на экране входа читается как «что-то сломано/опасно». Это информация, не предупреждение.
- **Мёртвая кнопка LinkedIn во втором слоте primary-стека** (`comingSoon: true`, disabled). Неработающий элемент на главной позиции CTA. Плюс: LinkedIn по ToS — 16+, т.е. для половины целевой аудитории он не наступит никогда.
- **GitHub — единственный рабочий полный вход.** Для аудитории 13–18 это фильтр: у значительной части школьников GitHub-аккаунта нет. Осознанный продуктовый выбор (верификация) — но тогда на /auth нужна одна строка «нет GitHub? создать — 2 минуты» со ссылкой, иначе это тупик.
- **Фикс. паддинг `px-10` на мобильном** (`Auth.tsx:61,78,90`) против `px-5 sm:px-10` на Welcome. На 320–375px теряется 80px ширины, форма 420px и так не влезает.

**Рекомендация:** одна активная primary-кнопка (GitHub), Google — вторичная с бейджем «просмотр без аккаунта» без warning-стилистики, LinkedIn убрать из стека в строку-примечание, текст баннера сократить до одного предложения без слова «Builder». `px-10` → `px-5 sm:px-10`.

### 4. Три CTA одинакового веса на hero
`Welcome.tsx:160–195`. Sign up (primary) + Log in (ghost) + Contest (ghost с pulse-точкой). В коде честно написано: контест — «the strongest reason a first-time visitor has to care», но визуально он третий и самый слабый. Для новичка Log in бесполезен, а Contest — главный крючок.

**Рекомендация:** Contest поднять до второго по весу (или дать баннер-строкой над hero), Log in увести в header.

### 5. Onboarding: LinkedIn-косплей для школьников
`Onboarding.tsx`. Age-gate обязателен и сделан правильно (13+, guardian consent, без dead ends — не трогать). Но блок «Experience» (role / organization / duration / description) для 13–18 лет — пустое поле почти для всех и лишний экран трения на первом входе. Bio + discipline + interests достаточно.

**Рекомендация:** Experience убрать из онбординга, оставить в Settings/профиле.

### 6. «More official» — одна строка
`Welcome.tsx:232`: контакт в футере — `bshoxrux48@gmail.com`. Личный Gmail на лендинге подрывает «официальность» сильнее, чем любые цвета. Есть же `eengineer.team@gmail.com`, а лучше — адрес на своём домене.

## Не трогать (работает правильно)

- Палитра corn/dark и графбумага — контраст просчитан, комментарии в коде это фиксируют.
- Age-gate и «всё skippable» в онбординге.
- Решение «hero без скриншота» — протестировано, задокументировано.
- Blur-плейсхолдеры спонсоров — осознанный приём, не баг.
- Один брендовый жест (dimension line) — дисциплина уже в коде («one is a signature, two is a theme park»).

## Белый шум из чата (игнорировать)

«Как LinkedIn», «users care about functions» без конкретики, «поменять всё» → «ничего не менять» в пределах одного диалога, спор о пропорциях без данных. Ни один из этих пунктов не содержит воспроизводимой пользовательской проблемы.

## Порядок работ

1. /auth: упрощение копирайта и стека кнопок, mobile-паддинги — max 1 день, максимальный эффект на конверсию signup.
2. Hero sub-copy: первая строка = что это. 30 минут.
3. Футер: контактный email. 5 минут.
4. Переключатель темы на pre-auth — закрывает «eye strain» по-настоящему.
5. Onboarding: убрать Experience.
6. CTA-иерархия на hero (Contest вверх).

Пункты «перекрасить», «редизайн», «пропорции» — в бэклог не вносить: основания отсутствуют.
